# Go 语言学习笔记：方法（Methods）与接口（Interfaces）

## 一、 方法（Methods）

### 1. 什么是方法？
*   **定义**：方法是一个带有特殊接收者（Receiver）参数的函数。
*   **语法**：`func (接收者变量 接收者类型) 方法名(参数列表) 返回值 {}`
*   **本质**：方法就是普通函数，接收者只是被挪到了参数列表的第一个位置（语法糖）。它让代码具有面向对象的风格（`obj.Method()` 比 `Method(obj)` 更自然）。

### 2. 接收者（Receiver）的两种类型
接收者可以是值，也可以是指针，这决定了方法内部操作的是“复印件”还是“原件”。

| 特性             | 值接收者 `(v Type)`        | 指针接收者 `(v *Type)`               |
| :--------------- | :------------------------- | :----------------------------------- |
| **操作对象**     | 接收者的**副本**（拷贝）   | 接收者指向的**原始内存地址**         |
| **能否修改原值** | ❌ 不能，修改只对副本生效   | ✅ 能，直接修改原对象                 |
| **性能**         | 结构体大时，拷贝开销大     | 仅传递地址（8字节），开销小          |
| **使用场景**     | 小型结构体、不需要修改状态 | 需要修改状态、大型结构体、保持一致性 |

### 3. 方法调用的“语法糖”
Go 编译器非常智能，在**调用方法**时会自动进行指针/值的转换：
*   `v.Scale()` 如果 `Scale` 是指针接收者，编译器自动转为 `(&v).Scale()`。
*   `p.Abs()` 如果 `Abs` 是值接收者，编译器自动转为 `(*p).Abs()`。
*   **⚠️ 注意：这种自动转换只对“方法调用（`.`语法）”有效。如果是普通函数调用（如 `Func(v)`），类型必须严格匹配，该加 `&` 就得加。**

### 4. 最佳实践
*   **不要在同一个类型上混用值接收者和指针接收者。** 如果该类型有一个方法必须用指针接收者，为了代码一致性，建议该类型的所有方法都使用指针接收者（这也是 Go 社区最普遍的做法）。

## 二、 接口（Interfaces）

### 1. 什么是接口？
*   接口是一组**方法签名的集合**。
*   接口是一种抽象类型，它只定义“能做什么”，不关心“怎么做”。

### 2. 隐式实现（Implicit Implementation）
这是 Go 语言区别于 Java/C# 的核心特性。
*   **没有 `implements` 关键字**：只要一个具体类型拥有了接口中要求的所有方法（名称、参数、返回值完全一致），编译器就认为它实现了该接口。
*   **解耦**：接口的定义者和实现者不需要提前知道对方的存在，可以在不同的包里独立开发，极大地降低了代码耦合度。

### 3. 接口的底层结构 `(value, type)`
接口变量在底层是一个“胖指针”，包含两个部分：
1.  **`type`（动态类型）**：记录当前接口装的具体是什么类型（如 `*MyStruct`）。
2.  **`value`（动态值）**：记录当前接口装的具体数据值或指针。

**调用接口方法时**：Go 会根据底层的 `type`，去执行对应具体类型的同名方法（动态派发/多态）。

### 4. 接口实现规则（指针 vs 值）
*   如果方法是指针接收者 `func (v *T) M()`，那么**只有 `*T`（指针）**实现了接口。`T` 本身没有实现。
*   如果方法是值接收者 `func (v T) M()`，那么 **`T` 和 `*T` 都**实现了接口。

## 三、 ⚠️ 核心注意事项与避坑指南（重点）

这部分是 Go 初学者最容易翻车的地方，请务必牢记：

### 坑点 1：接口赋值时的严格性
*   **方法调用有语法糖，接口赋值没有！**
*   如果 `Abs()` 是指针接收者，而 `v` 是值：
    *   `v.Abs()` 合法（自动转 `(&v).Abs()`）。
    *   `var a Abser = v` **编译报错！** 必须写 `var a Abser = &v`。

### 坑点 2：nil 接口 vs 值为 nil 的接口
这是面试必考、开发必踩的终极陷阱。接口的零值是 `(nil, nil)`。

*   **状态 A：完全真空的 nil 接口**
    ```go
    var i I  // (nil, nil)
    ```
    *   `fmt.Println(i == nil)` 输出 `true`。
    *   调用 `i.M()` 会直接 **Panic（运行时崩溃）**，因为找不到类型，不知道调用谁的方法。

*   **状态 B：装了 nil 指针的接口**
    ```go
    var p *T // p 是空指针
    var i I = p // i 的底层是 (nil, *T)
    ```
    *   `fmt.Println(i == nil)` 输出 **`false`**！因为 `type` 部分不是 nil。
    *   调用 `i.M()` **可以正常运行**（不会崩溃），前提是 `M()` 方法内部做好了 `if receiver == nil` 的判断。
    *   **教训**：永远不要轻易用 `== nil` 去判断一个接口变量是否真的“空”。

### 坑点 3：大小写与包可见性
*   方法名大写开头（如 `Abs`）才能被其他包访问并用于实现接口。接口名和方法名必须完全一致（包括大小写）。

### 坑点 4：自定义类型与内置类型的区别
*   你可以给基于内置类型的自定义类型（如 `type MyInt int`）添加方法。
*   但你**不能**直接给内置类型（如 `int`、`string`）添加方法。

---

## 四、 一句话总结

**方法**赋予了数据类型“行为”，**接口**定义了这些行为的“契约”。Go 通过**隐式实现**降低了耦合，通过**底层 `(value, type)` 结构**实现了多态。掌握**指针与值的区别**以及**nil 接口的陷阱**，是写出健壮 Go 代码的关键。
