# JWT 鉴权与 Gin 中间件实战

## 一、为什么需要 JWT 鉴权？
之前写的备忘录接口是“裸奔”的，任何人知道 IP 和路径就能随意篡改数据。我们需要一种机制，证明请求是“合法用户”发出的。
**JWT（JSON Web Token）** 是一种无状态的认证方案。用户登录后，服务器用密钥生成一个加密字符串（Token）发给前端。前端后续请求带着这个 Token，服务器验证签名即可，不需要在服务器内存里存 Session。

## 二、JWT 的组成（必考）
一个完整的 JWT 通常长这样：`eyJhbG... (Header) . eyJ1c2VyX2lk... (Payload) . ZCqI... (Signature)`
1. **Header（头部）**：说明签名算法（如 HS256）。
2. **Payload（载荷）**：存放核心数据，比如 `user_id`、过期时间 `exp`。**注意：这部分只是 Base64 编码，不是加密，前端能解开看，所以千万别放密码！**
3. **Signature（签名）**：使用 `Header + Payload + 服务器私钥` 计算得出。黑客如果篡改了 Payload 里的 user_id，签名就对不上，验证失败。

## 三、核心代码实现

### 1. 工具层（utils/jwt.go）
- **生成 Token**：`jwt.NewWithClaims` 创建令牌，用 `jwt.MapClaims` 存入 `user_id` 和 `exp`（过期时间），最后用 `SignedString` 加上私钥生成字符串。
- **解析 Token**：`jwt.Parse` 传入前端传来的字符串，并在回调里返回你的私钥。解析成功后，从 `claims` 里把 `user_id` 强转出来（注意 JSON 数字默认是 float64）。

### 2. 中间件层（middleware/auth.go）
中间件就是一个在请求到达 Handler **之前** 执行的函数。
- **拦截逻辑**：
  1. 从 `c.GetHeader("Authorization")` 获取凭证。
  2. 校验格式必须是 `Bearer <token>`。
  3. 调用 `utils.ParseToken` 验证签名和过期时间。
  4. 失败则用 `c.Abort()` 终止请求，并返回 `401 Unauthorized`。
  5. 成功则用 `c.Set("user_id", userID)` 将用户信息存入上下文，并调用 `c.Next()` 放行。
