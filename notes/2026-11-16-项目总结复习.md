# 项目总结复习

## 第一部分：项目使用了哪些技术

1.Go：使用的编程语言。主打高并发，强类型，编译快

2.Gin：Web框架。只需要写路由和Handler，Gin会帮忙建好高速公路

3.GORM：ORM（对象关系映射）框架。类似翻译官，当想使用Go代码直接操作数据库，GORM帮你把Go语言翻译成SQL

4.SQLite：数据库。用的是一个纯Go版驱动的本地数据库，不需要像MySQL一样装个巨大的客户端，它就是个文件memo.db，存着数据

5.JWT（JSON Web Token）：一种鉴权技术。用户登录后，服务器发一张加密的通行证，用户以后拿着这张证来，服务器用密钥验证，不再存Session

6.Eino：字节跳动开源的Agent框架。专门用来处理大模型对话，工具调用，流式输出等复杂逻辑

7.SSE：服务器推送技术，让大模型吐出来的字能像打字机一样，通过HTTP一点点推给前端

## 第二部分：代码到底怎么组织

main.go/->程序入口，负责把一切串起来

router/->大堂经理，复制把不同的URL请求分发给对应的Handler

handler/->服务员：负责接客，处理HTTP请求

model/->仓库管理员：负责数据库的增删改查

middleware/->保安：负责安检（验JWT Token）

utils/->工具包：负责给Eino初始化大模型

tools/->给AI看的说明书（Function Calling）

因为它能自动把 Go 的结构体同步到数据库表结构，省去手写建表 SQL 的麻烦。，如果没有memos表，就帮你建一张。

// 2. 初始化聊天记录表

背后原理：同理，自动建好 `chat_histories` 表，用来存 AI 的记忆。

背后原理：初始化 DeepSeek。context.Background() 是 Go 的上下文，用来控制超时和取消。在这行里，它拿到了你的 API Key，生成了一个 ChatModel 实例。

## 第四部分：安检门与备忘录API的流转

假设你在 Apifox 发了一个 `GET /memos`。

1.router/router.go 拦截：

```go
memoGroup := r.Group("/memos")
memoGroup.Use(middleware.JWTAuth()) // 装上安检门
{
	memoGroup.GET("", handler.GetMemosHandler)
}
```

背后原理：路由分组。任何走 `/memos` 的请求，**必须**先经过 `JWTAuth()` 验证。

2.**`middleware/auth.go` 验票：**

```go
// 从请求头拿 token
authHeader := c.GetHeader("Authorization")
// 解析 JWT
tokenStr := strings.TrimPrefix(authHeader, "Bearer ")
userID, err := utils.ParseToken(tokenStr)
// 放行
c.Set("user_id", userID) // 把用户 ID 记录在上下文中
c.Next()
```

背后原理：解析 JWT，如果你没带 Token 或者 Token 是伪造的，直接 `c.Abort()` 打断请求。如果通过了，把用户信息存进 `c`（Gin 的上下文），后续 Handler 可以通过 `c.Get("user_id")` 直接拿到。

3.handler/memo.go 处理：

```go
func GetMemosHandler(c *gin.Context) {
	memos := model.GetAllMemos() // 调仓库管理员
	c.JSON(http.StatusOK, gin.H{"data": memos}) // 返回 JSON
}
```

4.**`model/memo.go` 查库：**

```go
func GetAllMemos() []Memo {
	var memos []Memo
	DB.Find(&memos) // GORM 翻译成 SELECT * FROM memos
	return memos
}
```

背后原理：GORM 底层把 `Find` 翻译成 SQL 发给 SQLite。

## 第五部分：智能AI记忆与工具调用

现在，你发了一个 `POST /chat`，说：“帮我记一条备忘录：多喝水”。

1.查记忆（handler/chat.go）

```go
history := model.GetRecentChats(userID, 10)
messages := []*schema.Message{}
for _, chat := range history {
    // 转换历史记录，塞进 messages
}
messages = append(messages, &schema.Message{Role: schema.User, Content: req.Prompt})
model.SaveChat(userID, "user", req.Prompt)
```

背后原理：先去数据库拿最近 10 条记忆，注意要**反转**（让时间正序）。然后把用户新说的话拼在最后。

2.组装大模型与说明书

```go
toolsList := tools.GetMemoTools()
ChatModelWithTools, _ := utils.ChatModel.WithTools(toolsList)
stream, _ := ChatModelWithTools.Stream(ctx, messages) // 开启流式请求
```

背后原理：把工具（`toolsList`）塞给大模型。大模型知道只要用户说“记一条”，它就能调用这个工具。这里用 `Stream` 开启流式请求，而不是 `Generate`，是为了打字机效果。

3.接收大模型的指令并处理

```go
for {
    chunk, err := stream.Recv() // 接收碎片
    if chunk.Content != "" {
        c.Writer.WriteString("data: " + chunk.Content + "\n\n")
        c.Writer.Flush()
    }
    if len(chunk.ToolCalls) > 0 {
        toolCalls = append(toolCalls, chunk.ToolCalls...)
    }
}
```

背后原理：大模型如果决定调工具，前面不会吐字。它会返回一个 `ToolCalls`，里面包含参数（比如 `{"content": "多喝水"}`）。代码用 `json.Unmarshal` 把它拆开，然后去调 `model.CreateMemo` 把数据存进数据库。

4.二次流式请求（完成闭环）：

```go
// 把工具执行的结果塞给大模型
messages = append(messages, &schema.Message{Role: schema.Tool, Content: "操作成功，ID为 5"})
// 再次开启流式请求
stream2, _ := ChatModelWithTools.Stream(ctx, messages)
for {
    // 接收并推流
}
```

背后原理：大模型收到了工具执行结果，它需要把这句冷冰冰的“操作成功”变成人话（“好的，已经为您记下”）。所以我们要发起**第二次流式请求**，让大模型一边说，我们一边把结果推给前端。
