# GORM 完整 CRUD 实战与防御性编程

## 一、今日目标达成
完成了备忘录 API 的完整闭环，实现了标准的 RESTful 接口：
- `GET /memos`（查询列表）
- `POST /memos`（新增）
- `PUT /memos/:id`（修改指定 ID）
- `DELETE /memos/:id`（删除指定 ID）

## 二、核心 GORM 函数与语法

### 1. 查询单条记录（用于修改前校验）
```go
var memo Memo
if err := DB.First(&memo, id).Error; err != nil {
    return memo, err
}
```
*   **`First`**：根据主键 ID 去查第一条记录。
*   **必须传指针 `&memo`**：GORM 需要把查到的数据塞进这个变量里。
*   **`.Error`**：提取本次查询的报错信息。如果数据库里没这个 ID，会返回 `gorm.ErrRecordNotFound`（记录不存在）。

### 2. 更新记录
```go
memo.Content = content
DB.Save(&memo)
```
*   先查出旧数据，修改字段后，用 `Save` 保存回数据库。GORM 会自动更新 `UpdatedAt` 时间。

### 3. 删除记录与防御性判断
```go
result := DB.Delete(&Memo{}, id)
if result.RowsAffected == 0 {
    return gorm.ErrRecordNotFound
}
return result.Error
```
*   **`Delete(&Memo{}, id)`**：告诉 GORM 去删 `memos` 表里 `id` 对应的数据。
*   **软删除**：GORM 默认不会真的把数据从硬盘抹掉，而是更新 `DeletedAt` 字段打个标记。这是为了安全，方便以后恢复。
*   **`result.RowsAffected`**：本次操作影响的行数。如果为 `0`，说明数据库里根本没有这条数据。必须主动抛出错误告诉前端，否则前端以为删成功了。

## 三、Handler 层的 URL 参数解析

当请求路径是 `/memos/1` 时，需要提取出 `1`：
```go
idStr := c.Param("id") // 注意是 Param 不是 Params
id, err := strconv.ParseUint(idStr, 10, 32)
```
*   **`c.Param("id")`**：提取 URL 路径里的参数，返回的永远是**字符串**。
*   **`strconv.ParseUint`**：因为数据库主键是数字类型，必须将字符串转成无符号整数（`uint`）。

## 四、今日踩坑记录

1. **`c.Params` 报错 `not a function`**：
   *   `c.Param` 是一个函数，用来获取特定参数。
   *   `c.Params` 是一个切片属性（存了所有参数），不能加括号调用。少敲一个 `s` 会导致编译报错。
2. **Apifox 提示红色的“失败”，但状态码是 200**：
   *   接口完全正常，数据也入库了。
   *   原因是 Apifox 自带的“后置操作/断言”功能，没匹配到它预期的字段。
   *   **解决办法**：去 Apifox 的后置操作里删掉自动生成的断言规则，只看 HTTP 状态码和返回的 JSON 即可。
