# Go 并发基础练习笔记

## 一、Goroutine 与 WaitGroup（并发打印）
**核心目标**：启动多个协程，并确保主程序等待它们全部执行完毕。

**关键知识点**：
1. `go func()` 启动一个协程，开销极小。
2. 主协程（`main`）退出时，所有子协程会被强制终止，所以必须阻塞等待。
3. **`sync.WaitGroup` 标准用法**：
   - `wg.Add(1)`：在启动协程前调用，表示增加一个任务。
   - `defer wg.Done()`：在协程内部调用，表示任务完成（建议放第一行）。
   - `wg.Wait()`：在 `main` 里调用，阻塞等待计数器归零。
4. **变量捕获坑**：在循环里启动协程，必须把循环变量作为参数传给匿名函数（`go func(i int){...}(i)`），否则所有协程可能读到同一个最终值。

## 二、生产者-消费者模型（Channel 基础）
**核心目标**：使用 Channel 在协程之间安全地传递数据。

**关键知识点**：
1. **无缓冲 Channel**：`ch := make(chan int)`。发数据时（`ch <- i`），必须有人接收才会继续，相当于同步握手。
2. **消费者的标准写法**：`for v := range ch`。它会自动等待数据，直到 channel 被关闭才会安全退出循环。
3. **谁负责关闭？** 永远由**生产者**在发完数据后调用 `close(ch)`。消费者不需要关闭。
4. **主程序同步方式**：可以用 `done := make(chan bool)` 接收结束信号，也可以用 `sync.WaitGroup`。

## 三、Select 超时控制
**核心目标**：防止调用外部接口（如网络请求、大模型）时无限期阻塞。

**关键知识点**：
1. `select` 用于同时监听多个 Channel，哪个有数据就执行哪个 `case`。
2. `time.After(duration)` 会返回一个 Channel，时间一到就会往里面发送数据。
3. 超时模式：
   ```go
   select {
   case res := <-ch:
       // 正常收到数据
   case <-time.After(2 * time.Second):
       // 超时兜底
   }
   ```
4. **遗留问题**：如果 `time.After` 先触发，后台那个正在干活的协程并不知道自己被抛弃了，会继续运行（协程泄漏）。

## 四、Context 上下文控制
**核心目标**：解决上述协程泄漏问题，实现树状结构的级联取消。

**关键知识点**：
1. 用 `context.WithTimeout(context.Background(), 2*time.Second)` 创建一个带超时的对讲机。
2. 一定要写 `defer cancel()`，防止资源泄漏。
3. `ctx.Done()` 返回一个 Channel，当超时或手动调用 `cancel()` 时，该 Channel 会收到信号。
4. **标准写法**：在后台协程里，利用 `select` 同时监听 `ctx.Done()` 和发数据操作，一旦收到取消信号，立即 `return` 释放资源。
