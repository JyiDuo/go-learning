# Go 语言并发编程核心笔记

## 一、 Goroutine（协程）：轻量级线程

**核心概念**：
Goroutine 是由 Go 运行时（Runtime）管理的轻量级线程。只需要在函数调用前加上 `go` 关键字，就能让该函数在一个新的 Goroutine 中并发执行。

**基本用法**：
```go
go f(x, y, z) // 开启一个新的 Goroutine 执行 f 函数
```
*   **特性**：
    *   主程序（`main` 函数）不会等待新开的 Goroutine 执行完毕，除非有特殊的同步机制。
    *   如果在当前 Goroutine 评估参数 `f, x, y, z`，实际的执行会在新的 Goroutine 中完成。
    *   所有 Goroutine 运行在同一个地址空间，因此访问共享内存必须同步（Go 提倡使用 Channel 来通信，而不是共享内存）。

---

## 二、 Channel（通道）：Goroutine 间的通信桥梁

**核心概念**：
Channel 是一种类型化的管道，你可以通过它发送和接收数值。它是 Go 语言并发模型的核心（CSP 模型：通过通信来共享内存，而不是通过共享内存来通信）。

**核心操作符**： `<-` （数据沿着箭头方向流动）
```go
ch <- v    // 发送：将 v 发送到通道 ch
v := <-ch  // 接收：从 ch 接收数据并赋值给 v
```

**创建方式**：通道必须使用 `make` 创建。
```go
ch := make(chan int) // 创建一个传递 int 类型的无缓冲通道
```

### 1. 无缓冲通道（Unbuffered Channel）
*   **特性**：默认情况下，发送和接收是**阻塞**的。发送方和接收方必须“严丝合缝”地配对。
    *   发送数据时，如果没有接收方，发送方会一直卡住（阻塞）。
    *   接收数据时，如果没有发送方，接收方会一直卡住（阻塞）。
*   **优点**：天然保证了同步，不需要显式地加锁。

### 2. 缓冲通道（Buffered Channel）
*   **创建方式**：在 `make` 时传入第二个参数指定容量。
    ```go
    ch := make(chan int, 100) // 容量为 100 的缓冲通道
    ```
*   **阻塞规则**：
    *   **发送**：只有当缓冲区**满**时，发送方才会阻塞。
    *   **接收**：只有当缓冲区**空**时，接收方才会阻塞。

## 三、 通道的关闭与遍历 (Close & Range)

**如何通知接收方“没有更多数据了”？**
发送方可以使用 `close(c)` 关闭通道，表示不会再有新数据发送。

**接收方如何优雅地处理？**
1.  **多返回值判断**：
    ```go
    v, ok := <-ch
    // 当通道关闭且数据取完时，ok 为 false，v 为该类型的零值。
    ```
2.  **`for range` 循环（推荐）**：
    ```go
    for i := range c {
        fmt.Println(i)
    }
    // 循环会不断接收数据，直到通道被 close 且数据全部取完，循环会自动结束。
    ```

**⚠️ 黄金法则**：
*   永远不要在接收端关闭通道，只有发送方才能关闭通道（在已关闭的通道发送数据会引发 panic）。
*   通道不像文件，通常不需要关闭。只有当接收方必须被告知“没有其他值进入”时（比如为了终止 `range` 循环），才需要关闭。

## 四、 Select 多路复用：处理多个通道

**核心概念**：
`select` 语句允许一个 Goroutine 在多个通信操作（Channel）上等待。它专门用于处理并发通道，类似于 `switch`，但每个 `case` 都是通道操作。

**基本用法**：
```go
select {
case msg1 := <-ch1:
    // 如果 ch1 有数据，执行这里
case ch2 <- msg2:
    // 如果 ch2 可以接收数据，执行这里
case <-quit:
    // 接收到退出信号
    return
}
```

**核心特性**：
*   `select` 会阻塞，直到其中一个 `case` 准备就绪，然后执行该 `case`。
*   如果有多个 `case` 同时准备就绪，Go 会**随机选择**一个执行（防止饥饿）。

---

## 五、 Default 默认选择：非阻塞通道操作

**核心概念**：
在 `select` 中加入 `default` 分支，可以避免 `select` 发生阻塞。

**用法与特性**：
```go
select {
case i := <-c:
    // 成功从 c 接收到数据
default:
    // 如果 c 中当前没有数据（其他 case 都不满足），立刻执行这里。
    // 这样就不会被阻塞，可以继续去干别的事情（如打印状态、执行其他逻辑）。
}
```

**⚠️ 致命陷阱**：
如果在 `for` 循环中使用了带 `default` 的 `select`，且 `default` 里的逻辑执行极快，会导致 CPU 疯狂空转（Busy Waiting）。
**解决方案**：在 `default` 中加入 `time.Sleep()` 让出时间片，避免占满 CPU。

## 六、 经典并发模式与避坑指南

### 1. 经典并发求和模式
将任务切片成两半，用两个 Goroutine 分别计算，将结果写入同一个通道，最后在主程序汇总。
```go
x, y := <-c, <-c // 从通道 c 接收两次（对应两个 Goroutine 发送的两次）
```

### 2. 生产者-消费者-停止模型 (使用 select)
*   使用一个数据通道（`c`）传递数据。
*   使用一个退出通道（`quit`）发送停止信号。
*   在 `select` 中同时监听 `c <- x`（继续生产）和 `<-quit`（停止生产）。

### 3. 常见死锁 (Deadlock) 场景
以下情况会导致 `fatal error: all goroutines are asleep - deadlock!`：
*   无缓冲通道只发送，不接收（或只接收，不发送）。
*   主程序试图接收超过通道内数据总量的次数（比如发了两次，接收了三次）。
*   使用了 `for range` 读取通道，但发送方忘记执行 `close(c)`。

### 4. IIFE 立即执行函数 (Immediately Invoked Function Expression)
在开启 Goroutine 时，经常会搭配匿名函数：
```go
go func() {
    // ... 代码 ...
}() // 最后的 () 代表立刻执行这个匿名函数
```
