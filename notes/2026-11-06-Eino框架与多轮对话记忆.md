# Eino 框架入门与多轮对话记忆实战

## 一、为什么要引入 Eino 框架？
昨天我们使用 `resty` 手写 HTTP 请求调用大模型，虽然能跑通，但在实际的 Agent 开发中：
1. 多轮对话需要手动拼接极其复杂的 JSON 数组。
2. 未来需要接入不同的模型（如通义千问、Kimi、GPT），手写代码需要重写 HTTP 请求。
3. 无法方便地使用流式输出（SSE）和工具调用（Function Calling）。

**Eino** 是字节跳动开源的 Go 语言大模型应用框架，专门解决上述问题，提供强类型、模块化的组件。

## 二、Eino 核心语法与概念

### 1. 初始化 ChatModel
在 `utils/agent.go` 中，我们使用 DeepSeek 的适配器初始化模型：
```go
apiKey := os.Getenv("DEEPSEEK_API_KEY")
if apiKey == "" {
    return fmt.Errorf("环境变量未配置")
}

ChatModel, err = deepseek.NewChatModel(ctx, &deepseek.ChatModelConfig{
    APIKey:  apiKey,
    Model:   "deepseek-chat",
    BaseURL: "https://api.deepseek.com",
})
ChatModel：Eino 的模型实例。把它定义成全局变量，方便 Handler 调用。

deepseek.ChatModelConfig：配置了 API Key、模型名称和请求地址。底层封装了所有的 HTTP 细节。

2. 多轮对话记忆（Message 列表）
为了让 AI 记住上下文，我们需要在请求时传入历史消息。在 Eino 中，消息使用 schema.Message 结构：

go
messages := []*schema.Message{
    {Role: schema.User, Content: "我叫张三"},
    {Role: schema.Assistant, Content: "你好张三，很高兴认识你！"},
    {Role: schema.User, Content: "我叫什么名字？"},
}
schema.User：代表用户提问。

schema.Assistant：代表 AI 的回复。

把历史对话按顺序放进切片中，Eino 会自动把整个列表发给大模型。模型就能通过上下文，正确回答“你叫张三”。

3. 调用生成回答
go
resp, err := ChatModel.Generate(ctx, messages)
// resp 是一个 *schema.Message
fmt.Println(resp.Content)
Generate：Eino 的方法，传入上下文和消息列表，返回生成的回答。
